What Ultron changed in v2 — flagged for your review

Some of these touch jarvis.py, your lane. They were made at Greyson's explicit request, are covered by tests, and are in the PR for you to review — push back in the PR if you disagree.

  • Environment awareness: new env_context() in jarvis.py injects the live local date, weekday and time into every model turn as reference data (never saved to history). Fixes Jarvis saying "Good morning" at 10:13 PM.
  • JARVIS_FAST mode (env flag; the server defaults it on, JARVIS_FAST=0 restores your original behaviour): your per-message pipeline cost 3–6+ model calls — a search-decision call, a routing call, then one per specialist. In fast mode the search-decision call is skipped (search still runs for an explicit look up ...), specialists are chosen by local keyword match (fast_roles(), max 2, no routing call), so a normal message costs one model call. Motivation: the search-decision call once turned the question "29x37" into Wikipedia results about the Porsche 911 (991).
  • Instant arithmetic: in fast mode, pure calculations (29x37, "what is 29 x 37?") are evaluated locally by a strict AST walker (arithmetic()) with zero model calls.
  • generate() now sends keep_alive (env JARVIS_KEEP_ALIVE, default 30m) so the model stays loaded.
  • Server/HUD (Ultron's lane, no review needed): chats now persist per user as JSON, GET /api/chats lists them, GET /api/chats/<id> returns history, DELETE removes; the HUD has a Chats panel to swap between chats like ChatGPT, and reopens the most recent chat on load.
